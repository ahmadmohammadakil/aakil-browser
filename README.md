# AAKIL — متصفحك الخاص

AAKIL هو متصفح شخصي بواجهة عربية من اليمين إلى اليسار، يبدأ بإصدار Windows 10/11 ويحتفظ بمسار Android لاحقًا. الإصدار الحالي من إعادة بناء Windows هو **0.2.1**، ويستخدم Electron مع Chromium لعرض صفحات الويب داخل التطبيق عبر `WebContentsView`، بدل الاعتماد على `iframe` أو WebView فرعي من Tauri.

## ما يعمل في الإصدار 0.2.1

تتضمن الواجهة صفحة بداية عربية، تبويبات متعددة، شريط عنوان وبحث، رجوعًا وتقدمًا وإعادة تحميل، اختصارات سريعة، الوضع الخاص، سجلًا محليًا قابلًا للمسح، مؤشرات حماية محلية، إعدادات، تبديلًا بين الوضع النهاري والليلي، وفتح الرابط في المتصفح الافتراضي.

تُنشأ كل صفحة ويب من العملية الرئيسية في Electron داخل `WebContentsView` مستقل. لا تحتاج Google والمواقع التي تمنع iframe إلى السماح بالتضمين؛ فهي تُحمّل كصفحة Chromium أصلية داخل مساحة التبويب. وتصل واجهة React إلى وظائف المتصفح عبر `preload` محدود الصلاحيات.

يحفظ AAKIL سجل الزيارات محليًا في `localStorage` فقط. عند تفعيل الوضع الخاص لا تُضاف الزيارات الجديدة إلى سجل AAKIL. لا يتضمن المشروع حاليًا مدير كلمات مرور أو مزامنة سحابية أو إرسالًا مركزيًا لسجل التصفح.

## الخصوصية والأمان

تُحمّل صفحات المواقع البعيدة مع تعطيل `nodeIntegration` وتفعيل `contextIsolation` وsandbox. كما يمنع AAKIL طلبات أذونات المواقع تلقائيًا في الطبقة الحالية. هذا إعداد دفاعي أولي، وليس شهادة أمان مستقلة أو بديلًا عن مراجعة متخصصة.

> لا تثق بأي متصفح مبني من مصدر غير موثوق لحماية حسابات حساسة قبل التحقق من التحديثات والتوقيع الرقمي وسياسات التنزيل والأذونات.

## حالة VPN

زر VPN الموجود في الواجهة هو **واجهة مستقبلية صادقة** وليس نفقًا فعليًا. لا يملك المشروع خادم VPN أو حساب مزود أو ملف WireGuard مضمّنًا، ولذلك لا يُدّعى وجود اتصال VPN حاليًا.

عند إضافة الوحدة لاحقًا، يكون المسار المناسب استيراد ملف WireGuard يملكه المستخدم أو إضافة تكامل رسمي مصرح به. يجب عدم تضمين حسابات مجانية لمزودي VPN أو مشاركة مفاتيح خاصة داخل التطبيق أو مستودع GitHub.

## التشغيل المحلي

يتطلب التشغيل المحلي Node.js وpnpm. بعد تثبيت الاعتماديات، يشغّل الأمر التالي خادم Vite وتطبيق Electron معًا:

```bash
pnpm install
pnpm electron:dev
```

لفحص الواجهة فقط:

```bash
pnpm run build
```

## البناء السحابي لويندوز

يحتوي المشروع على سير عمل GitHub Actions في `.github/workflows/windows-build.yml`. عند رفع تغيير إلى فرع `main` أو تشغيل العملية يدويًا من تبويب **Actions**، يبني GitHub نسخة Windows x64 على خادم Windows ويُخرج مُثبّت NSIS باسم مشابه لـ:

```text
AAKIL-0.2.1-Windows-x64-setup.exe
```

لا يحتاج جهاز المستخدم إلى Rust أو Visual C++ لهذا المسار؛ البناء يتم على خادم Windows. بعد نجاح العملية، افتح آخر تشغيل ناجح ونزّل artifact باسم `AAKIL-Windows-x64-Electron-MSI` للتثبيت التقليدي، أو `AAKIL-Windows-x64-Electron-NSIS` إذا أردت مُثبّت EXE.

## بناء الحزمة محليًا

يمكن بناء الواجهة والحزمة غير المثبتة عبر:

```bash
pnpm run build
pnpm exec electron-builder --win dir --publish never
```

ولإنشاء مُثبّت Windows على جهاز Windows:

```bash
pnpm run electron:dist
```

يستخدم المشروع الآن `electron-builder` مع مُثبّت MSI تقليدي عبر WiX، إضافة إلى مُثبّت NSIS. كلاهما ينشئ اختصار سطح المكتب وقائمة Start، بينما يبقى MSI هو خيار التسليم المفضل لتقليل التباس Windows مع ملفات EXE.

## Android لاحقًا

إصدار Android ليس جزءًا من إعادة بناء Windows الحالية. سيُعاد تقييم مساره بعد استقرار تصفح Windows، لأن Android يحتاج غلافًا وتجربة أذونات وتنزيلات مختلفة. لا يُعتمد أي APK حاليًا.

## البنية

| الجزء | التقنية أو الحالة |
|---|---|
| الواجهة | React 19 + TypeScript + Vite |
| غلاف Windows الحالي | Electron 44 + Chromium |
| تبويبات الويب | `WebContentsView` من العملية الرئيسية |
| جسر الواجهة | preload آمن مع `contextBridge` وIPC محدود |
| التخزين الحالي | `localStorage` محلي |
| المظهر | ليلي افتراضيًا ونهاري اختياري، مع حفظ الاختيار |
| VPN | واجهة اختيارية غير مفعّلة |
| Android | مسار لاحق غير معتمد بعد |

## ملفات مهمة

| الملف | الوظيفة |
|---|---|
| `src/App.tsx` | واجهة AAKIL وإدارة الحالة والتبويبات والسجل والمظهر |
| `src/App.css` | تخطيط RTL والمظهران النهاري والليلي |
| `electron/main.cjs` | نافذة Electron وWebContentsView والتنقل والأذونات |
| `electron/preload.cjs` | جسر IPC محدود الصلاحيات بين الواجهة والعملية الرئيسية |
| `electron/dev.cjs` | تشغيل Vite وElectron معًا في التطوير |
| `.github/workflows/windows-build.yml` | بناء مُثبّت Windows ورفع artifact |

## التحقق المنفذ

نجح فحص TypeScript وبناء Vite، ونجح فحص صياغة ملفات Electron، كما نجح إنشاء نسخة Windows غير مثبتة عبر `electron-builder --win dir`. وبُني مُثبّت Electron NSIS سحابيًا بنجاح، ويجري الآن التحقق من إخراج MSI التقليدي أيضًا. تم اختبار تشغيل Electron محليًا تحت بيئة رسومية افتراضية؛ بقيت عملية التطبيق مفتوحة دون خطأ بدء تشغيل قاتل. ويجب اختبار المُثبّت النهائي على Windows فعليًا للتأكد من التثبيت والعرض والتنقل.
